## Configuration contract

`resolveEnvironment(env)` is pure: no ambient env reads, dotenv, provider construction or connection. `environment.js` resolves once; nested objects are frozen. Only executable server entrypoint loads dotenv, before imports. Tests preload noDotenv and supply explicit disposable targets. Changing process.env after import is not a supported hot-reload mechanism; restart with validated env. Test-only policy spies are identified as mocks; pure strict-config tests and real server startup checks cover admission separately.

- NODE_ENV: missing defaults development; allowed development/test/staging/production. Staging/production require JWT_SECRET, JWT_REFRESH_SECRET, MONGODB_URI, FRONTEND_URL, SEPAY_API_KEY, SEPAY_BANK_ACCOUNT, SEPAY_BANK_NAME, REDIS_URL, REDIS_NAMESPACE, TRUST_PROXY. All server modes additionally require the existing Mongo/JWT/Cloudinary/SePay server fields. No sid-less strict fallback; stable refresh secret still required across instances.
- PORT: integer 1–65535, default 3001. ORDER_EXPIRY_HOURS: finite positive hours (technical Date range bound), default 24. BCRYPT_COST: integer 10–15, default 12. These validations reject invalid inputs previously coerced/fallback; they are admission changes, not business refactors.
- JWT_EXPIRES_IN: actual login/session access lifetime, default 15m. Explicit positive whole-second durations use ms/s/m/h/d/w; unitless strings rejected rather than interpreted as milliseconds. Tests inspect exp-iat on actually issued access JWT. JWT_ACCESS_EXPIRES_IN remains legacy helper-only, default 30m. JWT_REFRESH_EXPIRES_IN remains legacy helper-only (7d helper default; existing config property 30d default); neither changes B04 opaque family expiry, always absolute 30 days. No sliding family lifetime added.
- TRUST_PROXY keeps 0/1/loopback/linklocal/uniquelocal. LOG_LEVEL keeps Pino enums with production info and other modes debug defaults. CI accepts true/false/1/0; missing false, empty/invalid reject.
- MONGODB_URI supports Mongo/SRV seed forms; default local rs0 URI only in non-strict resolver, but server still requires explicit target. REDIS_URL supports redis/rediss; strict uses TLS rediss. REDIS_NAMESPACE defaults totmart:development outside strict, shape checked. Explicit empty REDIS_URL remains a documented local/test disable, forbidden in strict modes.
- FRONTEND_URL defaults localhost:3000, CORS_ORIGINS defaults frontend; lists normalize trailing slashes as before. Origins must be valid HTTP(S) origins, public HTTPS in strict modes. Optional provider fields may be absent outside server/strict requirements; defined empty fields reject. Missing, empty and invalid are distinguished in errors using key/reason only.

Admission differences are explicit: invalid/empty numeric/unit/enum/URL values no longer silently fall back; essential server fields fail before model/provider imports; config is immutable; direct production validator no longer echoes rejected origin text. No HTTP response/status/cookie/CSRF, role, ownership, idempotency or transaction policy change. Existing runtime legacy-money check remains production-only; B05 does not silently extend that unrelated business gate to staging.

Source asymmetry preserved explicitly: missing Idempotency-Key is rejected by the helper in production; other modes, including staging, retain the existing generated-key fallback. Safe callers must always supply/retain a stable key regardless of environment. Strict staging sessions do not silently change this separate commerce policy in B05; the partial spec marks the header conditionally required rather than claiming it is required everywhere.

## Lint and format

Pinned dev tooling: ESLint 10.13.0 / @eslint/js 10.0.1 (Node >=24 supported), Prettier 3.9.10, Ajv 8.17.1 and swagger-parser 10.1.1. Runtime dependency versions are not intentionally upgraded. Registry marked ESLint 9 unsupported during setup; switched before baseline publication. Prettier 3.6.2 and 3.9.10 both exposed a non-idempotent one-line response chain; expanded its object literal without changing AST/values before the checked formatter phase. No ignore/disable added. Install reported 20 moderate advisories across the full dev tree; no audit fix or unrelated upgrade.

Before source edits, recommended correctness rules found 23 errors: 19 no-unused-vars, one each no-useless-catch/no-useless-escape/no-case-declarations/no-unsafe-finally. Raw lint exits 1. An early CLI run additionally exposed 3 false no-undef reports for __dirname because dynamic globalThis differed from node -e; Node globals were made explicit before publishing baseline, preserving initial evidence in artifacts. No source errors were hidden by that correction.

`tooling/lint-baseline.json` retains the frozen pre-refactor debt: original byte hashes, all 23 issue locations, pinned version and semantic rule/global policy hash. `npm run lint` always scans every source/script/test and root JS config. Debt is allowed only when the LF-normalized fingerprint still matches; only CRLF to LF is normalized, never spaces, tokens or code. This makes Windows and Linux checkout behavior equivalent. Paid-down/changed baseline files have no LF exemption (null), so their old errors cannot be reintroduced. Any changed or new/untracked file must have zero errors/warnings. CI uses the same mechanism without a merge base or clean Git tree. No broad ignore or inline disables; changed rules/version require explicit review. Old debt remains visible through `npm run lint:all` (expected nonzero until paid down).

The LF metadata extension preserves the original byte-hash baseline in `artifacts/b05/lint-baseline.pre-lf.json`, keeps every initial issue, and only fixes platform classification. `tooling/b05-input-lf-hashes.json` applies the same rule to formatter scope; original input digests are unchanged. Tests prove CRLF/LF equality, inequality for whitespace/code edits and rejection of a real new untracked error in both CI modes.

Exceptions: no-unused-vars ignores argument and caught-error bindings because Express/Jest/driver callback signatures and deliberate catch handling use them; variable declarations still checked. Node24/CommonJS globals and Jest test globals are explicit. No suppression for transaction/security code. The unused jwt catch/rethrow wrapper was removed preserving the exact thrown error object.

Phases are recorded independently: tooling/baseline before runtime edits; config refactor before formatter; formatter only on B05 changed/new code/JSON and new inventory/index docs, not the whole repository. `--debug-check` verifies formatter AST stability; acceptance uses `npm run format:check`. Legacy unmodified files are not forced through a formatter. Historical evidence documents are retained byte-for-byte in B05.
