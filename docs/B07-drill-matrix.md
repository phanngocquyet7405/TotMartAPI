# B07 drill plan and evidence matrix

Written before faults. All targets are newly provisioned fixture capabilities, not environment URLs. One fault at a time; stop on ownership uncertainty, unauthorized access, lost receipt, duplicate obligation, negative stock or broken money equations. Never use FLUSH, bulk process kills, shared volumes or production providers. Test records use synthetic values. No raw requests, cookies, tokens, user data or credential URI in evidence.

Each result will be recorded in [B07 verification](B07-verification.md). Existing B04/B06 scenarios are reused as regression evidence, not counted again as independent new experiments.

## Planned drills

1. **B06 conflict assertion (planned).** Target: helper-created private Mongo replica set. Request: duplicate provider identity with changed amount. Before/after: every business collection; permit updatedAt only on the target event, keep every other receipt timestamp exact. Deadline 60s suite; stop on any other mutation. Cleanup uses owned helper handle. Evidence: selected suite counts and source hash.
2. **Redis outage/recovery (planned, existing HTTP suite reused).** Two backend fixture processes and exact-ID/label/binding Redis lease, plus a different observer Redis. Stop/start then separately pause/unpause. Health 503, limiter bounded failure, DB family revocation authoritative, remote SSE closure/heartbeat fallback, outbox pending then drain, unrelated family DB/access preserved, observer PONG unaffected. Existing deadlines and assertions retained (limiter 5s request bound, SSE 23s observation under 25s poll); restore before next fault. No late commerce obligation may appear from failed limiter requests. Evidence: existing HTTP/B04/B06 artifacts on final B07 snapshot, not historical counts alone.
3. **Mongo single-node outage (planned).** Two backends, newly owned Docker Mongo replica set and separate Redis. Verify exact ID, label, configured loopback binding before pause/unpause. Pause with no active mutation; read health/auth/attempt/create must fail within request deadline, never 2xx auth bypass. Unpause, wait PRIMARY/readiness, reuse original key and resolve/terminate. Compare order/checkout/stock/coupon/allocation/refund fingerprints before/after. Request deadline 15s, recovery 30s. Parent driver may also stall while Mongo paused, so take snapshots only before pause/after recovery. This is a single-node outage, not multi-node failover.
4. **Mongo commit uncertainty (planned if failpoint supported).** Same owned test-only mongod with enableTestCommands. Inject one commitTransaction error labelled UnknownTransactionCommitResult, observe real driver's commandFailed label and transaction retry, then clear failpoint. Assert one checkout/stock/coupon effect under same key. This is a server-injected unknown result; it does not simulate a response lost after an actually committed Mongo transaction. Separate existing pre-commit death and post-commit HTTP-loss tests remain distinct. Failover/partition/true post-commit lost ACK are not-run unless separately implemented.
5. **Workers (planned).** Same private DB, two backend fixture instances invoke real exported scheduler drains. Run expiry and delivery scheduling, reconciliation, notification outbox and security outbox separately. Use test-only barriers/error hooks around claim/write/publish; no production control endpoint. Verify state/revision/unique keys, no premature fulfillment/notification, backlog drain after restart/expired claims, one durable business effect; transport duplicates are allowed only with dedup and labelled at-least-once. Observe within 30s per controlled step; finite child-command deadline. No external provider send. Cleanup restores hooks and stops exact children/leases.
6. **Migration/CAS rollback (planned).** Inventory B03 identity, merchant ownership, commerce flags, checkout reconstruction, ledger classification and box metadata scripts. Use private clone only, no index drop/sync or blanket unset. First fingerprint dry-run; create collision/mixed-owner/flags conflict. Review manifest in RAM with filtered counts/hash artifact; apply only reviewed conflict-free manifest; inject exception during apply, inspect atomicity, rerun; writer changes one migrated field before CAS rollback, expect conflict without clobber. Keep finance/tombstone/session/index fingerprints. Deadline 60s; stop on non-CAS overwrite or financial change. Existing identity index-drop workflow is review-only here because this B07 scope forbids dropping indexes to pass.
7. **Backup/restore (planned).** Docker mongodump/mongorestore on owned replica set; verify tools actually exist first. Seed real application models and indexes, quiesce all fixture writers/workers, dump DB, checksum and retain gzip archive under ignored artifact directory. Restore into a new namespace on the owned server, never --drop. Compare documents/counts, unique/TTL/partial indexes, references, ledger and restored replay/session/tombstone behavior. RPO: last fixture marker included, no acknowledged writes after quiesce. RTO: restore start through index/data verification and restored application read/replay; separately time dump and restore commands. Deadline 60s each tool/verification. Source backend stays stopped during restore; destination app has no business workers. Archive contains fixture only and is not committed. Local drill does not validate encryption/offsite/retention/PITR.
8. **Alert transport (planned).** Private admin summary source and loopback HTTP sink; no human messaging. Synthetic retry/outbox/refund/capacity conditions. Real alert dispatcher must deliver minimal allowlisted firing/recovery payload, dedup/rate-limit repeated firing, expose failed delivery state and retry after sink recovers. Thresholds are proposals from existing summary (15min queues, 24h refunds, >=8000 attempts/user, cap10000), not signed SLOs. Observe 5s send bound, retry manually per fixture to avoid sleeps. Keep counts/status only. Sink state and keys are disposable; restore any failed transport before cleanup.
9. **Bounded local load (planned).** One-node owned replica set, owned Redis, two app processes. Small exploratory dataset: two active load customers, one catalog merchant, ample stock, one fixed coupon, product and subscription fixtures. Route mix browse/quote (40%), prepare/create (10%), same-key replay (30%), authenticated synthetic webhook (20%). Warmup 4, concurrency 2, max20 measured requests, max30s load duration; new keys only for independent purchases (max4), stable key for replay/receipt identity. Stop on first invariant violation, >2 unexpected errors, or request deadline 10s. Planned 429/outage503 classified separately; no faults overlap load. Measure p50/p95/errors, DB operations/connections/backlogs before/after and recovery; no target SLO, caching/index/timeout optimization. Snapshot money/order/stock/coupon/receipt invariants after quiet drain.

## Stop and cleanup protocol

Always recover a paused owned container in finally before stopping child handles. Stop workers before backup/restore/migration. Only capability-created ID/name/label/binding can authorize docker pause/stop/remove or exec writes; known external names/env do not. Verify IDs absent after cleanup, not only cleaned=true. Preserve failed counts and filtered evidence. If prerequisites fail, mark the affected drill blocked and B07 unclosed; do not substitute a shared service or mock and claim success.
